    3. Einführung in die Webentwicklung ASP.NET

    3.1. Introduction

    Im vorigen Kapitel wurden die Grundlagen der Webentwicklung vorgestellt, die unabhängig von der verwendeten Programmiersprache sind. Derzeit dominieren drei Technologien den Markt der Webentwicklung:

    • J2EE, eine Java-Entwicklungsplattform. In Verbindung mit der Struts-Technologie, die auf verschiedenen Anwendungsservern installiert ist, wird die Plattform J2EE vor allem in Großprojekten eingesetzt. Aufgrund der verwendeten Sprache – Java – kann eine J2EE-Anwendung auf den wichtigsten Betriebssystemen (Windows, Unix, Linux, Mac OS, …) laufen.
    • PHP ist eine interpretierte Sprache, die ebenfalls betriebssystemunabhängig ist. Im Gegensatz zu Java handelt es sich hierbei nicht um eine objektorientierte Sprache. Die Version PHP5 soll jedoch Objekte in die Sprache einführen. Da PHP einfach zu handhaben ist, wird es häufig in kleinen und mittleren Projekten eingesetzt.
    • ASP.NET ist eine Technologie, die nur auf Windows-Rechnern mit der Plattform .NET (XP, 2000, 2003, …) läuft. Als Entwicklungssprache kann jede mit .NET und c.a.d kompatible Sprache verwendet werden. Es gibt mehr als ein Dutzend davon, angefangen bei den Sprachen von Microsoft (C#, VB.NET, J#) über Delphi von Borland bis hin zu Perl, Python, ...

    Im vorigen Kapitel wurden kurze Beispiele für jede dieser drei Technologien vorgestellt. Dieses Dokument befasst sich mit der Webentwicklung ASP.NET mit der Sprache VB.NET. Wir gehen davon aus, dass diese Sprache bekannt ist. Dieser Punkt ist wichtig. Wir befassen uns hier ausschließlich mit ihrer Verwendung im Kontext der Webentwicklung. Lassen Sie uns diesen Punkt näher erläutern, indem wir auf die MVC-Methodik der Webentwicklung eingehen.

    Eine Webanwendung, die dem Modell MVC entspricht, wird wie folgt aufgebaut sein:

    Eine solche Architektur, die als 3-Tier- oder 3-Schichten-Architektur bezeichnet wird, zielt darauf ab, das MVC-Modell (Model-View-Controller) einzuhalten:

    • Die Benutzeroberfläche ist die V (die Ansicht)
    • die Anwendungslogik ist das C (der Controller)
    • die Datenquellen sind das M (Modell)

    Die Benutzeroberfläche ist häufig ein Webbrowser, es könnte sich jedoch auch um eine eigenständige Anwendung handeln, die über das Netzwerk Anfragen an den Webdienst sendet und die von diesem zurückgesendeten Ergebnisse aufbereitet. Die Anwendungslogik besteht aus Skripten, die die Anfragen des Benutzers verarbeiten. Die Datenquelle ist oft eine Datenbank, es können aber auch einfache Textdateien, ein Verzeichnis LDAP, ein entfernter Webdienst usw. sein. Der Entwickler sollte darauf achten, eine weitgehende Unabhängigkeit zwischen diesen drei Komponenten zu wahren, damit bei einer Änderung an einer der Komponenten die beiden anderen nicht oder nur in geringem Umfang angepasst werden müssen.

    • Die Geschäftslogik der Anwendung wird in Klassen untergebracht, die von der Klasse getrennt sind, welche den Anfrage-Antwort-Dialog steuert. Somit könnte der oben genannte Block [Logique applicative] aus folgenden Elementen bestehen:

    Im Block [Logique Applicative] lassen sich unterscheiden:

    • die Controller-Klasse, die den Einstieg in die Anwendung bildet,
    • den Block [Classes métier], der die für die Anwendungslogik erforderlichen Klassen umfasst. Diese sind vom Client unabhängig.
    • den Block [Classes d'accès aux données], der Klassen enthält, die zum Abrufen der für das Servlet erforderlichen Daten notwendig sind, häufig persistente Daten (BD, Dateien, Dienst WEB, ...)
    • der Block der Seiten ASP, der die Ansichten der Anwendung bildet.

    In einfachen Fällen beschränkt sich die Anwendungslogik oft auf zwei Klassen:

    • die Controller-Klasse, die den Client-Server-Dialog sicherstellt: Bearbeitung der Anfrage, Generierung der verschiedenen Antworten
    • die Fachklasse, die vom Controller zu verarbeitende Daten erhält und ihm im Gegenzug Ergebnisse liefert. Diese Fachklasse verwaltet dann selbst den Zugriff auf die persistenten Daten.

    Die Besonderheit der Webentwicklung liegt in der Erstellung der Controller-Klasse und der Darstellungsseiten. Die Geschäfts- und Datenzugriffsklassen sind klassische .NET-Klassen, die sowohl in einer Webanwendung als auch in einer Windows-Anwendung oder sogar in einer Konsolenanwendung verwendet werden können. Die Erstellung dieser Klassen erfordert gute Kenntnisse in der objektorientierten Programmierung. In diesem Dokument werden sie in VB.NET geschrieben; wir gehen daher davon aus, dass diese Sprache beherrscht wird. Vor diesem Hintergrund ist es nicht notwendig, sich ausführlicher als nötig mit dem Code für den Datenzugriff zu befassen. In fast allen Büchern über ASP.NET ist ein Kapitel dem Thema ADO.NET gewidmet. Das obige Schema zeigt, dass der Datenzugriff über ganz klassische .NET-Klassen erfolgt, die nicht wissen, dass sie in einem Webkontext verwendet werden. Der Controller, der sozusagen der Teamleiter der Webanwendung ist, muss sich nicht um ADO.NET kümmern. Er muss lediglich wissen, von welcher Klasse er die benötigten Daten anfordern muss und wie er dies tun soll. Das ist alles. Das Einfügen von ADO.NET-Code in den Controller entspricht nicht dem oben erläuterten MVC-Konzept, und wir werden dies nicht tun.

    3.2. Die Tools

    Dieses Dokument richtet sich an Studierende, daher werden wir mit kostenlosen Tools arbeiten, die im Internet heruntergeladen werden können:

    • die Plattform .NET (Compiler, Dokumentation)
    • die Entwicklungsumgebung WebMatrix, die den Webserver Cassini mit sich bringt
    • verschiedene SGBD (MSDE, MySQL)

    Der Leser wird gebeten, den Anhang „Web-Tools“ zu konsultieren, in dem angegeben ist, wo diese verschiedenen Tools zu finden sind und wie sie installiert werden. In den meisten Fällen benötigen wir nur drei Tools:

    • einen Texteditor zum Schreiben der Webanwendungen.
    • ein Entwicklungstool VB.NET zum Schreiben des VB-Codes, wenn dieser umfangreich ist. Ein solches Tool bietet in der Regel Unterstützung bei der Codeeingabe (automatische Code-Vervollständigung) sowie die Anzeige von Syntaxfehlern entweder bereits während der Codeeingabe oder bei der Kompilierung.
    • einen Webserver zum Testen der geschriebenen Webanwendungen. In diesem Dokument wird Cassini verwendet. Leser, die über den Server IIS verfügen, können Cassini durch IIS ersetzen. Beide sind mit .NET kompatibel. Cassini ist jedoch darauf beschränkt, nur lokale Anfragen (localhost) zu beantworten, während IIS auch Anfragen von externen Rechnern beantworten kann.

    Eine hervorragende kommerzielle Entwicklungsumgebung für VB.NET ist Visual Studio.NET von Microsoft. Dieses sehr umfangreiche IDE ermöglicht die Verwaltung aller Arten von Dokumenten (VB.NET-Code, HTML-Dokumente, XML, Stylesheets usw.). Beim Schreiben von Code bietet es die wertvolle Hilfe der automatischen Code-Vervollständigung. Allerdings hat dieses Tool, das die Produktivität des Entwicklers deutlich steigert, den Nachteil seiner Vorzüge: Es zwingt den Entwickler in einen zwar effizienten, aber nicht immer geeigneten Standard-Entwicklungsmodus.

    Es ist möglich, den Cassini-Server außerhalb von [WebMatrix] zu nutzen, und genau das werden wir häufig tun. Die ausführbare Datei des Servers befindet sich in <WebMatrix>\<version>\WebServer.exe, wobei <WebMatrix> das Installationsverzeichnis von [WebMatrix] und <version> dessen Versionsnummer ist:

    3.3. Erste Beispiele

    Wir werden einfache Beispiele für dynamische Webseiten vorstellen, die mit VB.NET erstellt wurden. Der Leser ist aufgefordert, diese zu testen, um zu überprüfen, ob seine Entwicklungsumgebung korrekt installiert ist. Wir werden feststellen, dass es mehrere Möglichkeiten gibt, eine ASP.NET-Seite zu erstellen. Wir werden eine davon für die weiteren Entwicklungen auswählen.

    3.3.1. Grundlegendes Beispiel – Variante 1

    Benötigte Werkzeuge: ein Texteditor, der Cassini-Webserver

    Wir greifen das Beispiel aus dem vorherigen Kapitel wieder auf. Wir erstellen die folgende [heure1.aspx]-Datei:

    <html>
  <head>
      <title>Demo asp.net </title>
  </head>
  <body>
      Il est <% =Date.Now.ToString("T") %>
  </body>
</html>

    Dieser Code ist der Code HTML mit einem speziellen Tag <% ... %>. Innerhalb dieses Tags kann man Code VB.NET einfügen. Hier der Code

    Date.Now.ToString("T")

    eine C-Zeichenkette, die die aktuelle Uhrzeit darstellt. Das Tag <% ... %> wird dann durch diese C-Zeichenkette ersetzt. Wenn C also die Zeichenkette 18:11:01 ist, wird die Zeile HTML, die den Code VB.NET enthält, zu:

          Il est 18:11:01

    Speichern wir den obigen Code in der Datei [<webroot>\chap2\heure1.aspx]. Starten wir Cassini (<webroot>,/aspnet) und rufen wir mit einem Browser die Seiten URL und [http://localhost/aspnet/chap2/heure1.aspx] auf:

    Sobald dieses Ergebnis vorliegt, wissen wir, dass die Entwicklungsumgebung korrekt installiert ist. Die Seite [heure1.aspx] wurde kompiliert, da sie Code aus VB.NET enthält. Bei der Kompilierung wurde eine DLL-Datei erzeugt, die in einem Systemordner gespeichert und anschließend vom Cassini-Server ausgeführt wurde.

    3.3.2. Einfaches Beispiel – Variante 2

    Benötigte Tools: ein Texteditor, der Cassini-Webserver

    Das Dokument [heure1.aspx] enthält sowohl HTML-Code als auch VB.NET-Code. In einem so einfachen Beispiel stellt dies kein Problem dar. Wenn jedoch weiterer Code aus VB.NET eingebunden werden soll, ist es ratsam, den Code aus HTML stärker vom Code aus VB zu trennen. Dies kann erreicht werden, indem der Code VB innerhalb eines <script>-Tags zusammengefasst wird:

    <script runat="server">

</script>

</html>

    Das Beispiel [heure2.aspx] veranschaulicht diese Methode:

    3.3.3. Einfaches Beispiel – Variante 3

    Benötigte Tools: ein Texteditor, der Cassini-Webserver

    Wir treiben die Trennung des Codes VB und des Codes HTML weiter voran, indem wir sie in zwei separate Dateien auslagern. Der Code HTML wird in der Datei [heure3.aspx] enthalten sein und der Code VB in der Datei [heure3.aspx.vb]. Der Inhalt von [heure3.aspx] lautet wie folgt:

    
<%@ Page Language="vb" src="heure3.aspx.vb" Inherits="heure3" %>
<html>
    <head>
        <title>Demo asp.net</title>
    </head>
    <body>
        Il est
        <% =maintenant %>
    </body>
</html>

    Es gibt zwei grundlegende Unterschiede:

    • die Anweisung [Page] mit noch unbekannten Attributen
    • die Verwendung der Variablen [maintenant] im Code HTML, obwohl sie nirgendwo initialisiert ist

    Die Anweisung [Page] dient hier dazu, anzugeben, dass sich der Code VB, der die Seite initialisiert, in einer anderen Datei befindet. Das Attribut [src] gibt diese an. Wir werden feststellen, dass es sich bei dem Code VB um den einer Klasse namens [heure3] handelt. Für den Entwickler transparent wird eine .aspx-Datei in eine Klasse umgewandelt, die von einer Basisklasse namens [Page] abgeleitet ist. In diesem Fall muss unser Dokument HTML von der Klasse abgeleitet sein, die die Daten definiert und berechnet, die es anzeigen soll. Hier ist dies die Klasse [heure3], die in der Datei [heure3.aspx.vb] definiert ist. Außerdem muss diese Eltern-Kind-Beziehung zwischen den Dokumenten VB, [heure3.aspx.vb] und den Dokumenten HTML, [heure3.aspx] angegeben werden. Dieses Attribut [inherits] legt diese Verknüpfung fest. Es muss den Namen der Klasse angeben, die in der Datei definiert ist, auf die das Attribut [src] verweist.

    Betrachten wir nun den Code VB auf der Seite:

    Public Class heure3
    Inherits System.Web.UI.Page

     ' Anzuzeigende Daten der Webseite
    Protected maintenant As String

    Private Sub Page_Load(ByVal sender As System.Object, ByVal e As System.EventArgs) Handles MyBase.Load
         'Die Daten der Webseite werden berechnet
        maintenant = Date.Now.ToString("T")
    End Sub
End Class

    Beachten Sie bitte Folgendes:

    • Der Code VB definiert eine Klasse [heure3], die von der Klasse [System.Web.UI.Page] abgeleitet ist. Dies ist immer der Fall, da eine Webseite stets von [System.Web.UI.Page] abgeleitet sein muss.
    • Die Klasse deklariert ein geschütztes (protected) Attribut [maintenant]. Es ist bekannt, dass ein geschütztes Attribut in den abgeleiteten Klassen direkt zugänglich ist. Dies ermöglicht es dem Dokument HTML [heure3.aspx], in seinem Code auf den Wert der Daten [maintenant] zuzugreifen.
    • Die Initialisierung des Attributs [maintenant] erfolgt in einer Prozedur [Page_Load]. Wir werden später sehen, dass ein Objekt vom Typ [Page] vom Webserver über eine Reihe von Ereignissen benachrichtigt wird. Das Ereignis [Load] tritt ein, wenn das Objekt [Page] und seine Komponenten angelegt wurden. Der Handler für dieses Ereignis wird durch die Direktive [Handles MyBase.Load] festgelegt 
        Private Sub XX(ByVal sender As System.Object, ByVal e As System.EventArgs) Handles MyBase.Load
    • Der Name [XX] des Ereignis-Handlers kann beliebig sein. Seine Signatur muss jedoch der oben angegebenen entsprechen. Wir werden diese vorerst nicht näher erläutern.
    • Häufig wird der Ereignis-Handler [Page.Load] verwendet, um die Werte der dynamischen Daten zu berechnen, die auf der Webseite angezeigt werden sollen.

    Die Dokumente [heure3.spx] und [heure3.aspx.vb] werden in [<webroot>\chap2] abgelegt. Anschließend wird mit einem Browser die Datei URL [http://localhost/aspnet/chap2/heure3.aspx] vom Webserver (<webroot>,/aspnet) angefordert:

Beim Cassini-Server entspricht dieses Stammverzeichnis dem Parameter /path, mit dem Sie ihn gestartet haben.     3.3.6. Einfaches Beispiel – Variante 6

    Benötigte Werkzeuge: ein Texteditor, der Cassini-Webserver

    Wir haben bisher gezeigt, dass eine dynamische Webanwendung aus zwei Komponenten besteht:

    1. Code VB zur Berechnung der dynamischen Teile der Seite
    2. HTML-Code, der manchmal VB-Code enthält, um diese Werte auf der Seite anzuzeigen. Dieser Teil stellt die Antwort dar, die an den Web-Client gesendet wird.

    Komponente 1 wird als Controller-Komponente der Seite bezeichnet, Teil 2 als Präsentationskomponente. Die Präsentationskomponente sollte so wenig VB-Code wie möglich enthalten, am besten gar keinen VB-Code. Wir werden sehen, dass dies möglich ist. Hier zeigen wir ein Beispiel, bei dem es nur einen Controller und keine Präsentationskomponente gibt. Der Controller generiert die Antwort an den Client selbst, ohne die Hilfe der Präsentationskomponente.

    Der Präsentationscode sieht dann wie folgt aus:

     <%@ Page src="heure6.aspx.vb" Language="vb" AutoEventWireup="false" Inherits="heure6" %>

    Man sieht, dass darin kein HTML-Code mehr enthalten ist. Die Antwort wird direkt im Controller erstellt:

    Public Class heure6
    Inherits System.Web.UI.Page

    Private Sub Page_Load(ByVal sender As System.Object, ByVal e As System.EventArgs) Handles MyBase.Load
         ' die Antwort wird erstellt
        Dim HTML As String
        HTML = "<html><head><title>heure6</title></head><body>Il est "
        HTML += Date.Now.ToString("T")
        HTML += "</body></html>"
         ' die Antwort wird gesendet
        Response.Write(HTML)
    End Sub
End Class

    Der Controller generiert hier die gesamte Antwort und nicht nur deren dynamische Teile. Außerdem sendet er sie ab. Dies geschieht über die Eigenschaft [Response] vom Typ [HttpResponse] der Klasse [Page]. Es handelt sich um ein Objekt, das die vom Server an den Client gesendete Antwort darstellt. Die Klasse [HttpResponse] verfügt über eine Methode [Write], um in den Datenstrom HTML zu schreiben, der an den Client gesendet wird. Hier speichern wir den gesamten zu sendenden Datenstrom HTML in der Variablen [HTML] und senden diese über [Response.Write(HTML)] an den Client.

    3.3.7. Fazit

    Im Folgenden werden wir Methode 3 verwenden, bei der der Code „VB“ und der Code „HTML“ eines dynamischen Webdokuments in zwei separate Dateien aufgeteilt werden. Diese Methode hat den Vorteil, dass eine Webseite in zwei Komponenten aufgeteilt wird:

    1. eine Controller-Komponente, die ausschließlich aus dem Code VB besteht, um die dynamischen Teile der Seite zu berechnen
    2. eine Präsentationskomponente, die die an den Client gesendete Antwort darstellt. Sie besteht aus HTML-Code, der manchmal VB-Code zur Anzeige der dynamischen Werte enthält. Wir werden stets darauf hinarbeiten, so wenig VB-Code wie möglich im Präsentationsteil zu haben, wobei es ideal wäre, gar keinen zu haben.

    Wie in Methode 5 gezeigt wurde, kann der Controller unabhängig von der Webanwendung kompiliert werden. Dies hat den Vorteil, dass man sich ausschließlich auf den Code konzentrieren kann und bei jeder Kompilierung eine Liste aller Fehler erhält. Sobald der Controller kompiliert ist, kann die Webanwendung getestet werden. Ohne vorherige Kompilierung übernimmt der Webserver diese Aufgabe, und die Fehler werden dann einzeln gemeldet. Dies kann als mühsam empfunden werden.

    Für die folgenden Beispiele reichen folgende Werkzeuge aus:

    • ein Texteditor zum Erstellen der Dokumente HTML und VB der Anwendung, sofern diese einfach sind
    • ein Entwicklungswerkzeug wie IDE oder .NET zum Erstellen der Klassen VB.NET, um von der Unterstützung dieses Werkzeugs beim Schreiben von Code zu profitieren. Ein solches Tool ist beispielsweise CSharpDevelop (http://www.icsharpcode.net). Ein Anwendungsbeispiel ist im Anhang [Les outils du développement web] dargestellt.
    • das Tool WebMatrix zum Erstellen der Präsentationsseiten der Anwendung (siehe Anhang [Les outils du développement web]).
    • den Cassini-Server

    Alle diese Tools sind kostenlos.
